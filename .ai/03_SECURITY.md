# 安全与隐私

时钟的数据留在本机。v1 的网络只有天气。

## 权限

| 权限 | 何时要 | 拒绝之后 |
|------|--------|----------|
| `INTERNET` | 天气开关打开且已有城市或正在搜索 | 天气槽隐藏 |
| `ACCESS_COARSE_LOCATION` | 用户打开「使用当前位置」时再申请 | 保持手动城市，不反复弹窗 |
| 其他 | v1 不申请 | — |

不要申请精确定位、后台定位、通知、精确闹钟、前台服务、常驻唤醒锁。专注页的常亮只用窗口标志 `FLAG_KEEP_SCREEN_ON`，离开该页就清除。

## 网络

只访问这两台主机，且只用 HTTPS：

- `geocoding-api.open-meteo.com`
- `api.open-meteo.com`

这是 Open-Meteo 的公开非商业接口，不放置 API 密钥。若以后改用他们的商业客户域名，密钥来自用户或本机不入库的配置，仍然禁止写进仓库和 `.ai/`。

调用节制：

- 一个城市。
- 前台可见时，缓存未过 30 分钟不刷新。
- 搜索由用户提交触发，不在输入每个字时打满请求。可以在本地做很短的防抖，但失败和空结果必须可见于设置页。

预报字段收窄到当前温度、当前天气代码、当日最高和最低。时区参数用 `auto`。温度用摄氏度。地理编码语言用 `zh`。

## 天气失败

| 情况 | 钟面 | 设置页 |
|------|------|--------|
| 开关关闭 | 无槽，无请求 | 显示已关闭 |
| 没有城市 | 无槽 | 提供搜索 |
| 无结果 | 保持原城市 | 说明没找到 |
| 网络失败且无缓存 | 无槽 | 说明暂时拿不到天气 |
| 网络失败但有缓存 | 显示缓存 | 可以说明更新时间 |

钟面不出现异常文本、URL 或堆栈。

## 定位

粗略定位只在用户打开「使用当前位置」后取一次。Open-Meteo 没有反向地理编码，允许的两台主机也给不出中文地名，所以不调用 Nominatim 或其他主机。取到坐标后，显示名记为「当前位置」，纬度和经度照常保存，之后按这对坐标刷新天气，不持续跟踪。没取到位置、或用户拒绝权限时，保留原来的城市，不反复弹窗。坐标只存在应用私有目录。关掉「使用当前位置」不删除已选城市。点选搜索结果会关掉这个开关，并换成点选的城市。

## 本地数据

- 设置：DataStore 文件 `clock_settings`。现在有小时制 `hour_mode`、日期开关 `show_date`、主题 `theme`、配色 `colorway`（目前只有墨黑），天气开关、是否使用当前位置、一个城市和一份缓存，以及防烧屏开关 `burnin_enabled`、无操作时长 `burnin_idle_millis`、运行时长 `burnin_run_millis`。屏保进行到哪一步不落盘。专注结束时刻留到 M5，不提前写入。防烧屏不申请新权限，不改系统亮度，不加唤醒锁。
- 纪念日：应用私有目录里的一个 JSON 文件，上限 30 条。
- 不做账号，不做上传。系统自动备份可以包含这些偏好；里面没有密钥。

## 依赖与供应链

- 农历计算依赖 `cn.6tail:lunar`，许可证 MIT。不把农历规则抄进自己的代码。
- 翻页外观只参考 FlipClock 的翻折和 FliTik 的页片分组。不复制二者的字体、截图、音效或源码。若要捆绑数字字体，只用许可证允许再分发的字体，并在关于页署名。
- 不加载用户提供的图片 URL，不做账号。背景只来自应用自己绘制的颜色。
- 不引入会扩大攻击面的远程代码、WebView 天气页、任意 URL 加载。
- 关于页用文字链接到 `https://open-meteo.com/`，作为数据来源说明。

## 输入

- 城市搜索词和纪念日标题去掉首尾空白后有长度上限（标题 1–20 个字符，搜索词 1–40 个字符）。
- 纪念日的月日必须能被对应日历解释。解释不了就拒绝保存。
- 防烧屏时长落在设计文档的闭区间内，越界值在写入前夹紧。
